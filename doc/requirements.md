# 《雾港最后一盏灯》需求文档

> 当前状态：第一款 Prolog × Story Session 整合实验的可替换产品提案。题材可以更换；权威状态、规则判定与恢复实验是本阶段固定目标。

## 1. Overview

玩家是暴风夜里临时接管旧港信号站的守灯人，需要在港区自由调查、调动物资、与两名关键角色建立合作，并在涨潮切断路线前恢复一条可信的归航信号，引导一艘失联渡船回港。

- **单次体验形态**：中等长度的连续叙事探索；第一版以 15–25 分钟完成一个章节为原型假设。
- **跨次连续性**：长期存档保留人物位置、物品归属、设备状态、关系、已知线索、潮汐阶段和所有选择结果。
- **停止点**：玩家可以在任意一次已提交行动后退出；回来时从最近的可读事件和当前有效选择继续。
- **回访理由**：继续未完成的救援，或在章节完成后重玩另一条修复路线和人物关系结果。
- **呈现方式**：累积阅读、自由输入和明确选择并存；图片只在新地点、关键修复和重要对话出现，不要求每回合生成。

核心循环：**调查或交涉 → Prolog 判定行动与规则结果 → 玩家看到确定性后果及叙事 → 选择下一条可行路线**。

### 承诺层级

- **第一个有效动作**：玩家亲手拿起风暴提灯，看到灯油进入权威物品状态，并立即获得一条可调查路线。
- **第一段体验**：玩家理解当前目标、反复行动和失败代价，并完成一次不受惩罚的真实设备检查。
- **前 10 分钟**：玩家遇见至少一名被可见介绍的角色，打开一个条件路线，并意识到物品、信任和设备状态会共同改变选择。
- **章节完成**：渡船得到一条真实可用的归航信号；采用的修复路线和人物承诺成为可恢复的结局状态。
- **回访**：继续未完成章节，或在明确重启后尝试不同的角色合作与资源分配。

### 首次理解合同

在第一次安全设备检查后，新玩家应该能回答：

1. 当前目标是恢复可信的归航信号；
2. 反复行动是调查、移动、使用物品和向角色求助；
3. 修复、线索、信任和信号稳定代表进展，错误路线会消耗灯油、镇定或救援窗口，但不会删除存档。

在获得真实新玩家复述证据前，标记为 `comprehension unverified`。

## 2. Visual Design

第一版采用深蓝暴风夜、氧化黄铜、湿木和暖色信号灯构成的港口悬疑世界。界面以可累积阅读的叙事流为主体，地图、人物、物品和三项状态作为次级信息层，当前可执行行动始终在最近事件之后清楚出现。

目标视口为 390×844、320×568、1024×768 和 1440×900；触控和鼠标均可使用。功能图标统一使用同一套 SVG 线性图标，不使用 Emoji。精确颜色、字体、构图、图标、动效和素材规则在视觉方向确认后写入 `doc/visual.md`。

## 3. Game Mechanics

### 核心动词

- 调查地点、设备、记录和可见痕迹；
- 在港区地点之间移动；
- 拾取、携带、交付和使用物品；
- 与角色交谈、求助、交换信息或作出承诺；
- 修复设备、开启条件路线并选择最终信号方案。

### 世界范围

首个纵向切片包含 6–10 个稳定地点、2 名可持续角色、1 件三格充能物品、至少 2 条条件路线、1 次复合修复判定和 1 个章节结局。未来角色在可见登场前不进入人物面板、关系、目标或选择。

### 三项可见状态

- **镇定 0–6，初始 4**：影响暴风压力下的恢复和高风险调查；降至 0 时必须先执行可行的撤回或恢复行动。
- **港区信任 0–6，初始 1**：决定角色是否带路、交付工具或证实冲突信息。
- **信号稳定 0–6，初始 1**：表示归航信号的可用程度；达到章节方案要求后才能完成救援。

单次普通变化不超过 2。所有变化由结构化规则进入权威 reducer，正文只叙述可感知后果，HUD 显示实际增减。

### 关键资源与确定性规则

风暴提灯初始有 3 格灯油。照亮淹水通道或读取黑暗设备标记各消耗 1 格；第一章只有一次可靠补充机会。物品使用、门锁、人物带路、设备修复、地点切换和结局条件由 Prolog 规则判定。

复合判定至少覆盖：指定零件已持有、路线仍开放、信任或替代工具满足其一、相关设备尚未修复。失败不能产生部分物品消耗或半完成设备状态。

### 危险与恢复

普通探索至少连续 2 回合、至多 4 回合后才允许出现一次环境压力；解决后至少间隔 2 回合。第一版没有身体战斗。危险响应是使用提灯确认落脚点、请已取得信任的港工带路，或退回信号站重新规划。

失败造成绕路、损失 1 格灯油、镇定下降 1、信任下降 1 或角色移动等可继续后果。刷新、重试和网络超时不得重新掷结果或重复消耗。

### 状态与恢复实验

- 同一个行动 ID 重放三次只能提交一次；
- 旧版本行动必须零写入并返回冲突；
- Prolog 不可用时不得推进故事状态；
- Story Session 提交后响应丢失，客户端必须按原行动 ID 找回结果；
- Prolog 服务重启后，玩家进度必须由 Story Session 快照恢复；
- 两个实验用户不能列出或修改彼此的会话。

## 4. Controls

- **触控/鼠标**：点击选择行动、地点、人物和物品；叙事流中的可滚动内容使用 `onClick`，避免触摸开始即误触。
- **自由输入**：玩家可提交一条受长度限制的自然语言行动；系统将其映射到一个明确动作或要求澄清，不猜测歧义目标。
- **键盘**：Tab 顺序覆盖主要控件，Enter 提交明确输入；不在开场或危险状态暴露无效数字快捷键。
- **异步反馈**：按下后立即显示提交状态并阻止重复提交；只呈现权威提交后的结果。

## 5. Win / Lose Conditions

第一章的完成条件是提交一种真实可用的归航信号方案，使信号稳定达到该方案阈值，并满足对应物品、设备和角色条件。章节完成后保留全部状态并允许回顾，不自动清空存档。

没有传统 Game Over。镇定归零、灯油耗尽、路线被淹或失去角色支持都会改变可行路线，但至少保留一个确定性撤回或恢复行动。只有玩家明确确认后才能重启；重启创建同一游戏内的新会话，不覆盖旧会话记录。

## 6. Sound Effects

- 拾取或放置物品：90–140 ms 的木质轻击与低音正弦叠加，峰值不超过 0.045；
- 合法行动提交：80–120 ms 的继电器短响；
- 条件不满足：160–220 ms 的低频双脉冲，不使用刺耳警报；
- 状态改善：180–260 ms 的温暖黄铜泛音；
- 状态受损：220–320 ms 的低沉风压和短衰减噪声；
- 关键修复或章节完成：一次 1.5–2.5 秒的浮标钟与远处汽笛组合；
- 环境层：每次进入地点只播放一次短海风、雨或机械环境床，恢复页面、静音切换和重渲染不自动重播。

所有声音由首次用户手势解锁，支持静音和 `prefers-reduced-motion` 对应的低刺激反馈；声音失败不阻塞行动提交。
